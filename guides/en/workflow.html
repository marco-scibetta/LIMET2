Workflow

The four main flows

Create a new project, create a new feature, handle a bug and analyze an undocumented project. Four short sequences, each with its commands.

1 · Create a new project

1

Launch the dashboard: /limet-dashboard → http://127.0.0.1:8787

2

In Init: project name + docs path (check Workspace if multi-module). One click → register + graphify + Qdrant ingestion.

3

In Setup: select the project and configure Qdrant, Ollama and DB (optional).

2 · Create a new feature

1

Open the Claude session in the project and run:

/limet-new "feature description"

Generates the documents in limet/changes/<slug>/.

2

Implement each task:

/limet-task 1

2-3 line brief, code, automatic change log.

3

Verify:

/limet-test

TEST_PLAN + TEST_EXECUTION with real outcomes.

4

Archive (only if verified):

/limet-archive

3 · Handle a bug

1

Report the bug:

/limet-bug "problem description"

Generates BUG_REPORT.md with root cause and regression test.

2

Implement the fix:

/limet-task N
3

Regression + archive:

/limet-test
/limet-archive

4 · Analyze an undocumented project

1

In the dashboard, page Analyze: select the project and click Request analysis.

2

In Claude Code on that project:

/limet-analyze

Generates the onboarding documents in docs/ (architecture, module-map, dependencies, conventions, glossary, non-technical summary).

Rule: never done without verification, never build/test autonomously, never commit/push without authorization.
